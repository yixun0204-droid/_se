# 國立金門大學校務資訊系統 專案報告

## 摘要

本專案以 Node.js 內建模組實作一套類似國立金門大學校務資訊系統的網站應用程式，命名為「國立金門大學校務資訊系統（示範）」。系統支援學生、教師與管理員三種角色，提供登入、公告、線上選課、課表、成績查詢、成績登錄、使用者管理、課程管理與公告管理等功能。整體採用伺服器端渲染（SSR）與 JSON 檔案儲存，不依賴任何第三方套件，可直接以 `node server.js` 啟動。

本報告說明專案的需求分析、系統設計、資料模型、功能實作、路由設計、安全性機制、測試策略與結果，以及目前限制與未來發展方向。

---

## 1. 專案簡介

### 1.1 背景與動機

校務資訊系統是大學日常運作的核心系統之一，學生用它查詢課表與成績、教師用它管理課程與登錄分數、行政人員用它維護帳號、課程與公告。透過實作一個簡化版的校務系統，可以整合並練習以下軟體工程主題：

- 多角色權限控制與身分驗證
- 伺服器端渲染與表單流程設計
- 關聯式資料的建模與查詢
- 資料驗證、錯誤處理與使用者回饋
- Web 安全性（密碼雜湊、Session、CSRF、XSS）
- 自動化整合測試

### 1.2 專案目標

1. 以 Node.js 內建模組建立可直接執行的三角色校務系統。
2. 支援學生選課、退選、課表、成績與公告等核心流程。
3. 支援教師查看修課名單、登錄成績與管理個人公告。
4. 支援管理員管理使用者、課程與全站公告。
5. 具備基本的 Web 安全防護與角色權限隔離。
6. 以自動化測試驗證主要功能與邊界情況。
7. 維持零外部依賴，降低安裝與執行門檻。

### 1.3 專案範圍

本專案聚焦於「校務系統的核心教學示範流程」，包含：

- 單一學期（115 學年度第 1 學期）的課程與選課管理
- 學生、教師、管理員三種角色
- 課程、選課、成績、公告、使用者等主要資料

不包含真實校務系統中的排課演算法、學籍異動、註冊繳費、跨學期歷程、圖書館、宿舍、教學評量等延伸模組。

## 2. 需求分析

### 2.1 使用者角色

| 角色 | 說明 | 主要需求 |
|------|------|----------|
| 學生 | 一般修課學生 | 查看公告、選課、退選、查看課表、查詢成績、維護個人資料與密碼 |
| 教師 | 授課教師 | 查看自己開設的課程、查看修課名單、登錄成績、發布與刪除個人公告 |
| 管理員 | 教務處行政人員 | 管理使用者、管理課程、管理全站公告、查看系統統計 |
| 訪客 | 未登入使用者 | 僅能瀏覽登入頁 |

### 2.2 功能需求

#### 學生端

1. 使用帳號密碼登入。
2. 在儀表板查看已選課程數、總學分、平均成績、通過學分、今日課程與最新公告。
3. 瀏覽與搜尋開放選課的課程。
4. 選課時檢查是否重複選課、是否額滿、是否與已選課程衝堂。
5. 退選課程；已有成績的課程不可退選。
6. 以週課表形式查看本學期課程。
7. 查看各科分數、等第、通過狀態、學分加權平均與 GPA。
8. 查看全部公告與單一公告內容。
9. 查看個人資料與本學期摘要。
10. 修改自己的密碼。

#### 教師端

1. 使用帳號密碼登入。
2. 在儀表板查看開課數、修課人次、公告數與課程清單。
3. 查看自己開設的所有課程。
4. 查看單一課程的修課名單。
5. 批次登錄或更新學生成績（0-100，留空表示未評分）。
6. 新增、刪除自己發布的公告。
7. 修改自己的密碼。

#### 管理員端

1. 使用帳號密碼登入。
2. 查看使用者總數、各角色人數、課程數、選課筆數與公告數。
3. 依角色篩選使用者。
4. 新增學生、教師或管理員帳號。
5. 重設使用者密碼。
6. 刪除使用者；不可刪除自己，教師仍有課程時不可刪除。
7. 新增、編輯、刪除課程。
8. 開放或關閉課程選課。
9. 查看課程詳細資料與選課名單。
10. 新增、編輯、刪除全站公告與設定置頂。
11. 修改自己的密碼。

### 2.3 非功能需求

| 類別 | 需求 |
|------|------|
| 安全性 | 密碼不可明文儲存；需具備 Session、CSRF、XSS 防護與角色權限檢查 |
| 可用性 | 介面需支援中文、具備清楚導覽與錯誤提示 |
| 相容性 | 支援現代瀏覽器與 Windows、macOS、Linux |
| 可維護性 | 模組分層清楚，路由、視圖、資料存取各自獨立 |
| 可測試性 | 主要流程需有自動化整合測試 |
| 可攜性 | 不依賴外部套件與資料庫伺服器 |
| 效能 | 適用於課堂示範與小型資料量，請求處理需非阻塞 |

### 3.4 資料模型

系統使用單一 JSON 檔 `data/db.json`，內含五個頂層欄位：`meta`、`users`、`courses`、`enrollments`、`announcements`。

#### 3.4.1 `meta`

| 欄位 | 型別 | 說明 |
|------|------|------|
| semester | string | 目前學期代碼，例如 `115-1` |
| semesterLabel | string | 學期顯示名稱 |
| seededAt | string | 示範資料建立時間 |

#### 3.4.2 `users`

| 欄位 | 型別 | 說明 |
|------|------|------|
| id | string | UUID |
| username | string | 登入帳號（小寫） |
| passwordHash | string | scrypt 雜湊值（十六進位） |
| salt | string | 隨機鹽值（十六進位） |
| role | string | `student`、`teacher`、`admin` |
| name | string | 姓名 |
| email | string | 電子郵件 |
| department | string | 系所或單位 |
| studentId | string \| null | 學號（學生） |
| employeeId | string \| null | 員編（教師／管理員） |
| createdAt | string | ISO 時間 |
| updatedAt | string | ISO 時間 |

#### 3.4.3 `courses`

| 欄位 | 型別 | 說明 |
|------|------|------|
| id | string | UUID |
| code | string | 課程代碼，例如 `CS101` |
| name | string | 課程名稱 |
| teacherId | string | 授課教師的 user id |
| credits | number | 學分數（1-6） |
| capacity | number | 人數上限（1-300） |
| semester | string | 學期代碼 |
| room | string | 上課地點 |
| schedule | array | 上課時段，元素為 `{ day, start, end }` |
| description | string | 課程說明 |
| open | boolean | 是否開放選課 |
| createdAt | string | ISO 時間 |
| updatedAt | string | ISO 時間（可能不存在） |

`schedule` 的 `day` 為 1-5（週一至週五），`start` 與 `end` 為節次 1-8。

#### 3.4.4 `enrollments`

| 欄位 | 型別 | 說明 |
|------|------|------|
| id | string | UUID |
| courseId | string | 課程 id |
| studentId | string | 學生 user id |
| semester | string | 學期代碼 |
| score | number \| null | 成績，`null` 表示未評分 |
| createdAt | string | ISO 時間 |
| updatedAt | string | ISO 時間（評分後更新） |

#### 3.4.5 `announcements`

| 欄位 | 型別 | 說明 |
|------|------|------|
| id | string | UUID |
| title | string | 公告標題（最多 120 字） |
| content | string | 公告內容 |
| authorId | string | 發布者的 user id |
| pinned | boolean | 是否置頂 |
| createdAt | string | ISO 時間 |
| updatedAt | string | ISO 時間（編輯後更新） |

#### 3.4.6 資料關聯

```text
users (teacher) 1 ──────< courses
users (student) 1 ──────< enrollments >────── 1 courses
users (author)  1 ──────< announcements
```

- 一位教師可開設多門課程。
- 一位學生可有多筆選課紀錄。
- 一門課程可有多筆選課紀錄。
- 一則公告由一位使用者發布。

## 4. 功能實作

### 4.1 登入與 Session

- 登入時以帳號查詢使用者，並以 `verifyPassword()` 驗證密碼。
- 驗證成功後由 `createSessionStore().create()` 產生：
  - 32 bytes 隨機 token 作為 Session ID
  - 24 bytes 隨機 CSRF token
- Session 儲存在伺服器記憶體中，有效期限 8 小時。
- 瀏覽器透過 `Set-Cookie: sid=...; HttpOnly; SameSite=Lax; Path=/` 保存 Session。
- 登出時刪除伺服器端 Session 並清除 Cookie。
- 登入失敗回傳 HTTP 401 並重新顯示登入頁，不建立 Session。

### 4.2 權限控制

`src/routes/guards.js` 提供 `requireLogin(ctx, role)`：

- 未登入：重新導向 `/login`。
- 已登入但角色不符：回傳 HTTP 403 錯誤頁。
- 角色正確：回傳 `true`，路由繼續執行。

所有學生路由要求 `student`、教師路由要求 `teacher`、管理員路由要求 `admin`。修改密碼路由僅要求已登入，不限角色。

### 4.3 學生端

#### 儀表板

- 以 `computeStudentStats()` 計算已選課程數、總學分、平均成績與通過學分。
- 依台灣時區取得目前星期，篩選當天課程。
- 顯示最新 3 則公告。
- 提供選課、成績、課表與個人資料的快速連結。

#### 線上選課

- 列出目前學期且 `open` 為 `true` 的課程。
- 支援以課程代碼、名稱或教師姓名搜尋。
- 每門課顯示：
  - 課程代碼、名稱、說明
  - 授課教師、學分、上課時間、地點
  - 目前人數／上限
  - 已選、額滿、衝堂或可選課狀態
- 選課流程檢查：
  1. 課程存在且屬於目前學期。
  2. 課程開放選課。
  3. 尚未選過該課程。
  4. 人數未達上限。
  5. 與已選課程無衝堂。
- 通過後新增選課紀錄並寫入 JSON。
- 退選時檢查選課紀錄存在，且尚未有成績。

#### 衝堂判斷

`findScheduleConflict()` 會逐一比對課程的每個時段：

```text
同一星期，且 slot.start <= other.end 且 slot.end >= other.start
```

若符合即視為衝堂，禁止選課並顯示衝突課程名稱。

#### 課表

- 以 `timetableHtml()` 產生週一至週五、第 1-8 節的表格。
- 將每門課的時段填入對應格子，顯示課程名稱、地點與教師。
- 下方另列出課程明細表。

#### 成績查詢

- 列出每門課的學分、分數、等第與通過狀態。
- 計算學分加權平均與 4.0 制 GPA。
- GPA 對照：

| 分數 | GPA |
|------|-----|
| 90-100 | 4.0 |
| 85-89 | 3.7 |
| 80-84 | 3.3 |
| 75-79 | 3.0 |
| 70-74 | 2.7 |
| 65-69 | 2.3 |
| 60-64 | 2.0 |
| 50-59 | 1.0 |
| 0-49 | 0 |

#### 公告與個人資料

- 公告列表支援置頂排序，點擊可查看詳細內容。
- 個人資料頁顯示姓名、帳號、學號、系所、Email、建立時間與本學期摘要。

### 4.4 教師端

#### 儀表板與課程列表

- 顯示教師開設的課程數量、總修課人次與公告數量。
- 課程列表包含代碼、名稱、時間、地點、人數、狀態。
- 教師僅能看到 `teacherId` 等於自己的課程。

#### 修課名單與成績登錄

- 課程詳細頁顯示學分、選課人數、上課時間與地點。
- 名單包含學號、姓名、系所、Email、分數輸入框與目前等第。
- 成績以表單一次送出，欄位名稱格式為 `score:<enrollmentId>`。
- 後端驗證：
  - 分數必須為 0-100 的數字。
  - 空白表示設為未評分（`null`）。
  - 任一筆不合法時整批不寫入，避免部分更新。
- 僅能登錄自己課程的成績。

#### 公告管理

- 教師可新增公告，可設定置頂。
- 教師只能刪除自己發布的公告。
- 嘗試刪除他人公告會被拒絕並顯示錯誤訊息。

### 4.5 管理員端

#### 儀表板

- 顯示使用者總數、學生數、教師數、管理員數。
- 顯示課程總數、開放中課程數、選課筆數與公告數量。
- 顯示最新公告與快速功能連結。

#### 使用者管理

- 支援依角色篩選。
- 新增帳號欄位：帳號、密碼、角色、姓名、系所、Email、學號、員編。
- 驗證規則：
  - 帳號需為 3-20 碼小寫英文、數字或底線。
  - 帳號不可重複。
  - 角色必須合法。
  - 姓名不可空白。
  - 密碼至少 6 個字元。
  - 學號與員編不可重複。
- 重設密碼：輸入新密碼後重新雜湊並儲存。
- 刪除使用者：
  - 不可刪除自己。
  - 教師仍有課程時不可刪除。
  - 刪除學生時一併移除其選課紀錄。
  - 刪除使用者時一併移除其發布的公告。
  - 同時銷毀該使用者的 Session。

#### 課程管理

- 課程表顯示代碼、名稱、教師、學分、時間／地點、人數、狀態與操作。
- 新增／編輯欄位：代碼、名稱、教師、學分、人數上限、地點、學期、上課時間、說明、是否開放選課。
- 上課時間支援文字格式，例如：
  - `週一 1-2`
  - `Mon 1-2, Wed 3-4`
  - `週一 1-2、週三 3-4`
- 解析後儲存為結構化時段陣列。
- 驗證課程代碼唯一、學分 1-6、人數上限 1-300、教師存在。
- 可切換課程開放狀態。
- 刪除課程時一併刪除相關選課紀錄。
- 可查看課程詳細資料與唯讀的選課名單。

#### 公告管理

- 列出全站公告，依置頂與時間排序。
- 可新增、編輯、刪除公告。
- 可設定置頂。
- 標題最多 120 字，標題與內容不可空白。

### 4.6 修改密碼

所有已登入使用者皆可透過 `/account/password` 修改密碼：

1. 驗證目前密碼。
2. 新密碼至少 6 個字元。
3. 兩次新密碼需一致。
4. 以新的鹽值重新雜湊並儲存。

## 6. 安全性設計

### 6.1 密碼保護

- 使用 `crypto.scryptSync(password, salt, 64)` 進行雜湊。
- 每位使用者擁有 16 bytes 隨機鹽值。
- 資料庫不儲存明文密碼。
- 驗證時使用 `crypto.timingSafeEqual()` 比較雜湊值，降低時序攻擊風險。

### 6.2 Session 管理

- Session token 由 `crypto.randomBytes(32)` 產生。
- Cookie 設定 `HttpOnly`，避免前端 JavaScript 讀取。
- Cookie 設定 `SameSite=Lax`，降低跨站請求風險。
- Session 有效期限為 8 小時。
- 登入成功會建立全新 Session，避免 Session 固定攻擊。
- 登出與刪除使用者時會清除對應 Session。

### 6.3 CSRF 防護

- 每個 Session 擁有獨立的 CSRF token。
- 所有表單皆包含隱藏欄位 `csrf`。
- 除 `POST /login` 外，所有 POST 請求在進入路由前檢查：
  - Session 是否存在。
  - 表單 token 與 Session token 是否一致（使用 `timingSafeEqual`）。
- 驗證失敗回傳 HTTP 403，不執行任何資料變更。

### 6.4 XSS 防護

- 所有使用者輸入在輸出至 HTML 前皆經過 `esc()` 跳脫：
  - `&` → `&amp;`
  - `<` → `&lt;`
  - `>` → `&gt;`
  - `"` → `&quot;`
  - `'` → `&#39;`
- 公告標題與內容、姓名、系所、課程說明等皆適用。
- 測試中包含 `<script>` 注入案例，確認輸出會被跳脫。

### 6.5 權限控制

- 每個角色路由皆呼叫 `requireLogin(ctx, role)`。
- 教師只能存取自己的課程與成績。
- 教師只能刪除自己的公告。
- 學生只能操作自己的選課紀錄。
- 管理員不可刪除自己。
- 管理員不可刪除仍有課程的教師。

### 6.6 其他防護

- 請求本文上限 1 MB，避免過大請求耗盡記憶體。
- 靜態資源路徑經 `path.resolve()` 正規化，防止路徑穿越。
- 回應加上 `X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN`、`Referrer-Policy: same-origin`。
- 使用者輸入皆轉為 `URLSearchParams` 解析，不拼接查詢字串，避免注入類問題。
- JSON 資料以原子寫入（先寫暫存檔再重新命名），降低寫入中斷造成檔案損毀的風險。

## 11. 已知限制

1. **資料儲存為單一 JSON 檔**：不支援交易、索引與高併發寫入，資料量大時效能有限。
2. **Session 存於記憶體**：伺服器重啟後所有使用者需重新登入；多程序部署時無法共享 Session。
3. **固定單一學期**：目前學期寫死於設定，無法切換歷史學期。
4. **無學分上限**：學生選課未檢查每學期學分上限。
5. **無加退選期間限制**：任何時間皆可選課與退選。
6. **無候補與抽籤機制**：額滿即無法選課。
7. **無先修課程檢查**：未檢查課程先修條件。
8. **成績僅有單一總分**：不支援平時、期中、期末等多元評量。
9. **公告僅支援純文字**：不支援附件、分類與富文本。
10. **無稽核紀錄**：未記錄誰在何時修改了哪些資料。
11. **無分頁與大量資料最佳化**：使用者、課程與公告皆一次載入。
12. **管理員無法編輯既有使用者資料**：僅能新增、刪除與重設密碼。
13. **重設密碼不會強制登出該使用者**：舊 Session 仍可能有效。
14. **無登入失敗次數限制**：未實作帳號鎖定或速率限制。
15. **無 HTTPS 終止**：正式部署需搭配反向代理與 TLS。
16. **課表僅顯示週一至週五第 1-8 節**：不支援週末與其他節次。
17. **無備份與還原機制**：需自行備份 `data/db.json`。
18. **無多語系**：介面固定為繁體中文。

## 12. 未來改進方向

1. **改用 SQLite 或 PostgreSQL**：取得交易、索引、併發與資料完整性。
2. **Session 持久化**：使用資料庫或 Redis 儲存 Session，支援多程序與重啟。
3. **多學期架構**：課程、選課與成績皆關聯學期，支援歷史查詢。
4. **加退選期間與學分上限**：依教務規則限制操作。
5. **候補與抽籤**：處理熱門課程的公平分配。
6. **先修課程與擋修**：建立課程依賴關係。
7. **多元成績評量**：平時、期中、期末與權重設定。
8. **稽核日誌**：記錄登入、異動與管理操作。
9. **分頁與搜尋最佳化**：支援大量資料。
10. **使用者資料編輯**：管理員可修改姓名、系所、角色等。
11. **強制登出與 Session 管理**：重設密碼後使舊 Session 失效。
12. **登入速率限制與帳號鎖定**：降低暴力破解風險。
13. **多因子驗證**：提升帳號安全。
14. **附件上傳與富文本公告**：支援檔案與格式。
15. **CSV 匯出**：匯出選課名單與成績。
16. **Email 通知**：選課結果、成績與公告通知。
17. **Docker 化與反向代理**：簡化部署並提供 HTTPS。
18. **更完整的自動化測試**：加入效能、安全與跨瀏覽器測試。

## 13. 心得與結論

本專案將課堂中的軟體工程概念整合為一個可實際操作的三角色校務系統。在實作過程中，主要獲得以下經驗：

- **需求到實作的轉換**：從角色與功能需求出發，逐步設計資料模型、路由與頁面。
- **權限設計的重要性**：不同角色能看到的資料與可執行的操作必須在伺服器端嚴格檢查，不能只依賴前端隱藏按鈕。
- **表單流程與使用者回饋**：POST 後重新導向、成功／錯誤訊息與表單驗證，能讓操作流程更清楚。
- **Web 安全實務**：密碼雜湊、Session Cookie 屬性、CSRF token 與 HTML 跳脫，都是實際系統不可或缺的基礎防護。
- **資料一致性**：刪除課程時需同步移除選課紀錄、刪除使用者時需處理相關資料，避免孤兒資料。
- **測試的價值**：透過整合測試模擬真實登入與表單操作，可以在短時間內驗證三種角色的主要流程。

整體而言，本專案已達成預定目標：以零外部依賴的方式實作具備學生、教師與管理員三種角色的校務資訊系統，並涵蓋登入、公告、選課、課表、成績、使用者管理與課程管理等核心功能。系統具備基本的安全防護、清楚的模組分工與 21 項通過的整合測試，適合作為課程專案與後續擴充的基礎。
